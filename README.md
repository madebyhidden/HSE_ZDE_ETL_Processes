Весь процесс разбит на три дага. Сначала скрипт генерирует фейковые сессии просмотров фильмов и тикеты с багами, сохраняя их в Mongo. 

Затем запускается основной ETL-процесс: данные вытягиваются из нереляционной базы, на лету трансформируются (парсятся даты, высчитывается длительность просмотра в минутах и время закрытия тикетов) и заливаются в Postgres. При загрузке используется upsert, чтобы в базе всегда были чистые данные без дублей при перезапусках. 

В самом конце третий даг строит на основе очищенных таблиц две аналитические витрины: одна показывает популярность контента на разных платформах, а вторая — скорость решения проблем техподдержкой.
